🔄 ADR-004: Использование Object Storage для хранения результатов сканирований

**Статус**: Принято  
**Дата**: 2025-11-10  
**Участники**: Backend Architect, DevOps Engineer, Data Engineer

---

### 1. Контекст и проблема
>"Как хранить результаты сканирований (тексты, метаданные, файлы) объемом до 1 ТБ/месяц с гарантированной доступностью 99.9% и обеспечить быстрый доступ для аналитики (PERF-007) в условиях санкционных ограничений?"

---

### 2. Архитектурно значимые требования (ASR)
| ID требования | Текст требования | Тип | Источник |
|---------------|------------------|-----|----------|
| SCAL-013 | Хранение 1+ ТБ данных с ростом 20%/мес | НФТ | Техзадание п.4.2 |
| PERF-007 | Доступ к файлам <2 сек | НФТ | Вывод из PERF-002 |
| REL-003 | Доступность 99.9% | НФТ | SLA п.3.1 |
| COST-001 | Оптимизация стоимости хранения | ФТ | Бюджетное ограничение |
| COMPLY-001 | Соответствие 152-ФЗ | ФТ | Требование безопасности |

---

### 3. Анализ альтернатив
| Требование \ Решение | Локальное хранилище | VK Cloud S3 | Yandex Object Storage |
|----------------------|---------------------|-------------|----------------------|
| SCAL-013 (Объем) | ❌ Ручное масштабирование | ✅ Автоматическое | ✅ Автоматическое |
| PERF-007 (Задержка) | ✅ <1 сек | ✅ <2 сек | ✅ <2 сек |
| REL-003 (Доступность) | ❌ 95-98% | ✅ 99.9% | ✅ 99.9% |
| COST-001 (Стоимость) | ⚠️ Капзатраты | ✅ Pay-as-you-go | ✅ Pay-as-you-go |
| COMPLY-001 (152-ФЗ) | ⚠️ Зависит от реализации | ✅ Сертифицировано | ✅ Сертифицировано |

---

### 4. Выбранное решение
**VK Cloud Object Storage** с многоуровневой структурой хранения:
```text
Бакет: security-scans-results
├── raw/           # Исходные данные (Standard)
├── processed/     # Обработанные данные (Standard)
└── archive/       # Архив (>90 дней, Cold)
```


**Конфигурация**:
- **Провайдер**: VK Cloud (российский)
- **Шифрование**: SSE-256
- **Версионирование**: Включено
- **Lifecycle Policy**: 
  - Переход на Cold Storage через 90 дней
- **Доступ**: Через IAM роли + CDN для ускорения доступа
- **Регион**: Москва (РФ)

---

### 5. Обоснование
- **SCAL-013**: Object Storage обеспечивает неограниченное масштабирование
- **REL-003**: 99.9% SLA российского провайдера
- **PERF-007**: CDN снижает задержку для пользователей из РФ
- **COST-001**: Многоуровневое хранение снижает стоимость
- **COMPLY-001**: Российский провайдер соответствует 152-ФЗ

---

### 6. Последствия
**✅ Позитивные**:
- **Соответствие требованиям законодательства РФ**
- **Данные хранятся на территории России**
- **Полная управляемость через Terraform/Ansible**

**⚠️ Негативные**:
- **Ограниченная геораспределенность (только РФ)**
- **Меньше инструментов аналитики vs AWS**

**🔧 Зависимости**:
- **ADR-003:** Результаты из Kafka сохраняются в Object Storage
- **ADR-001:** AI-модель читает данные напрямую из хранилища
